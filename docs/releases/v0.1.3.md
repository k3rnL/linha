# Linha 0.1.3

Linha 0.1.3 adds renewable application credentials, storage access for workers,
and administrative tools for recovering queues stranded on an unusable context.

## Changes

- OAuth 2.0 client credentials in the JVM SDK, with expiry-aware concurrent token
  renewal. Public API JWT authentication and browser OIDC have independent settings.
- Configurable browser OIDC scopes and clearer administrator membership diagnostics.
- Application storage through explicitly authorized Linha destinations, scoped
  client/worker sessions, reusable resource locks and a new Hadoop filesystem SDK.
  Provider storage credentials stay on the server.
- Status-only jobs that finish without allocating a managed result file.
- Batch cancellation and movement of queued or retrying requests to a compatible
  context version, preserving request IDs, payloads, retry history and result policy.
- Searchable context filters, local date/time inputs, page selection and centered
  confirmation dialogs in both global and context request views.
- Encrypted OIDC refresh credentials shared across server replicas. Refreshed identity
  and group membership remain authoritative within the configured session lifetime.
- Context-readable Spark driver names with full unique instance IDs, and a writable
  Ivy directory for Spark images running with arbitrary container UIDs.
- A statically linked server binary validated inside its runtime image.
- Standalone, searchable documentation with version snapshots on GitHub Pages.

## Upgrade

This release changes authentication configuration. Configure API validation under
`security.api` and browser login under `security.oidc`; administrator rules remain
under `security.admin`. Application clients use OAuth client credentials and mount
only their client secret when needed. See [client authentication](../client-authentication.md)
and [administrator setup](../admin-ui.md).

Back up PostgreSQL and stop the old server replicas before deploying all 0.1.3
replicas. Startup migrates the database to schema 12. Older binaries reject newer
schemas; binary rollback requires restoring a compatible database backup.
Requests and published result metadata remain durable across the upgrade.

Use matching 0.1.3 SDKs when rebuilding application clients and worker images.
Application storage requires explicit destination opt-in and adequate server
bandwidth and staging space. Application dataset files have a separate lifecycle
from retained job results. See [application storage](../application-storage.md).

Sign in again to obtain browser refresh credentials. Providers must issue refresh
tokens; the absolute `ui.sessionSeconds` limit still applies. Existing Spark drivers
retain their names until replaced, when the readable naming convention takes effect.

## Artifacts and validation

Images are `ghcr.io/k3rnl/linha/server:0.1.3` and
`ghcr.io/k3rnl/linha/spark-example:0.1.3`. Maven artifacts use `com.k3rnl`, version
0.1.3: the parent plus protocol, client, worker, Spark and Hadoop SDK modules, with
sources, API documentation, checksums and signatures. The GitHub release also
includes the Helm chart and its checksum.

Validation covers Go/PostgreSQL and race checks, JVM SDKs, browser interactions,
chart rendering, restart recovery, OpenAPI contracts, signed publication bundles
and documentation builds. Hosted release workflows validate the tagged commit
before publishing. External cluster and provider deployment policies still need
validation in the target environment.

See the [release comparison](https://github.com/k3rnL/linha/compare/v0.1.2...v0.1.3).
