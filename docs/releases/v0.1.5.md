# Linha 0.1.5

Linha 0.1.5 adds customizable server Pod scheduling to the Helm chart while
preserving the existing deployment defaults.

## Changes

- Configure native node affinity, Pod affinity, and Pod anti-affinity through
  the top-level `affinity` value.
- Replace server topology spread constraints through
  `topologySpreadConstraints`. Leaving it unset or `null` retains the existing
  soft hostname spread; `[]` disables chart-provided spreading.
- Continue using `nodeSelector` and `tolerations` alongside the new settings,
  with schema checks for scheduling value types.
- Server scheduling remains independent of driver and executor Pod templates.

See the [Helm values reference](../reference/deployment/helm.md#helm-affinity).
Custom topology constraints use native Kubernetes label selectors and replace
the default list completely.

## Upgrade

Existing values files need no changes. Runtime behavior, public APIs, SDK APIs,
and the database schema are unchanged from 0.1.4. There is no database migration
for this update. Placement overrides change the server Deployment's Pod template
and trigger its normal rolling update.

Use matching 0.1.5 chart, server, and worker artifacts. Older clients remain
compatible. Upgrades from before 0.1.3 must also follow the
[0.1.3 upgrade instructions](v0.1.3.md#upgrade).

## Validation

Chart render checks cover default placement, custom affinity and multiple spread
constraints, explicit disabling, invalid value types, release-specific selectors,
and independent worker templates. Local chart checks do not establish live
Kubernetes placement behavior. The release workflow runs runtime, PostgreSQL,
restart, and packaging checks before artifact publication.

See the [release comparison](https://github.com/k3rnL/linha/compare/v0.1.4...v0.1.5).
