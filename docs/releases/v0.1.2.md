# Linha 0.1.2

Linha 0.1.2 reduces Kubernetes API traffic from already deleted resources in
retired context history.

## Changes

- Stop per-name probes for stopped contexts and dead instances.
- Inventory managed Pods, Services and SparkApplications once per minute per
  server, including startup. An empty two-replica deployment needs six collection
  calls per minute, independent of retained history.
- Preserve cleanup of late creates and leftover Services using persisted intent,
  reconciliation ownership and UID-conditional deletion.
- Bound retries after inventory/deletion failure without interrupting active
  capacity, accepted-work draining, reactivation or retained results.

## Upgrade

Update every server replica to 0.1.2. This change needs no database migration,
additional RBAC, SDK upgrade or business worker rebuild. Older replicas keep the
previous polling behavior until replaced. Late orphan cleanup can wait until the
next successful minute sweep.

The unreleased OAuth SDK and independent API/browser configuration described in
development documentation are not part of this release.

## Artifacts and verification

Images are `ghcr.io/k3rnl/linha/server:0.1.2` and
`ghcr.io/k3rnl/linha/spark-example:0.1.2`. JVM artifacts use `com.k3rnl`, version
0.1.2, with sources, API documentation and signatures. The release includes the
Helm chart and checksum.

A fixture with 5,000 dead records and 100 controller ticks performs three
inventory requests with no per-name probes. Tests also cover pagination, UID
checks, competing controllers, late creation, failure backoff and reactivation.
Go/PostgreSQL/race, JVM, restart and specification checks passed.
See the [release comparison](https://github.com/k3rnL/linha/compare/v0.1.1...v0.1.2).
