# Linha 0.1.2

Linha 0.1.2 fixes excessive Kubernetes API traffic caused by repeatedly checking already deleted resources from retired contexts.

## Changes

- Remove stopped contexts and dead instances from frequent resource polling. Retained history no longer generates individual GET/DELETE requests for missing Pods, Services and SparkApplications.
- Inventory existing managed resources once per minute per server, including on startup. For an idle two-replica deployment with no managed resources, cleanup requires six collection requests per minute, independent of historical instance count.
- Preserve cleanup of late creates after failover/restart and legacy Services left behind after their driver disappears. Deletion requires a matching retired intent, context reconciliation ownership and the discovered resource UID.
- Bound cleanup retries after API failures while preserving active capacity reconciliation, accepted-work draining, context reactivation, and durable job/result history.
- Sync and archive the completed cleanup specification; document operational behavior and validation evidence.

## Upgrade

Update all server replicas to `0.1.2`. Old replicas retain the previous polling behavior until replaced. The Helm chart defaults to the new server image:

```yaml
image:
  repository: ghcr.io/k3rnl/linha/server
  tag: 0.1.2
```

Retain your existing deployment settings. No database migration, additional RBAC permissions, SDK upgrade or business worker image rebuild is required. SDKs are also published at `0.1.2` for consistent coordinates. Late orphan cleanup can wait until the next successful minute sweep; active capacity reconciliation keeps its existing cadence.

## Validation

Go checks/vet, PostgreSQL 17 integration and race tests, Java 17 Maven package, all-process restart smoke and strict OpenSpec validation passed locally. A regression with 5,000 dead records and 100 controller ticks makes three inventory requests with no per-name probes; other tests cover pagination, identity filtering, UID preconditions, competing replicas, late creates after restart, bounded failures, and Service-only cleanup. Tagged CI runs the complete validation suite before publishing.
