## Context
The server currently owns hand-built driver Pods and one immutable context per owner/name. This prevents stable names during rolling API updates and separates JVM heap selection from Pod resource construction.

## Goals / Non-Goals
Use Spark Operator v2.4.0 SparkApplication v1beta2 submission for new managed contexts, preserve engine-independent request durability, and retire unused versions only after accepted jobs finish. Do not install an operator in production, migrate user images automatically, delete retained results, or promise exactly-once side effects.

## Decisions
- Add application.mainClass/mainApplicationFile/arguments and SparkApplication-style memory, memoryOverhead, cores, coreRequest, coreLimit and javaOptions. Memory is heap; overhead is additional memory. Deprecated memoryMi remains a heap alias for migration. Default overhead follows Spark JVM rules (10%, minimum 384 MiB). Validate bounds and reject contradictory settings. Linha owns one SparkApplication per driver instance, restartPolicy Never, with operator-generated driver Pods. Preserve validated native templates, translating the reserved main container to Spark's native container names.
- New managed API requests require application launch settings. Persisted legacy contexts retain their Pod renderer. Instance records store resource kind and SparkApplication UID independently of the driver Pod UID. Observation verifies ownership and deletion uses UID preconditions; pending submissions are not mistaken for missing drivers.
- Hash canonical effective configuration including resolved primary image digest after defaults/template merging. Unique owner/name/version replaces owner/name; configuration and result policy are immutable within a version. Resolve tags at ensure; job submission remains immediate after a durable insert. Keep stored IDs and results. Idempotency is scoped by owner/logical name/key across versions and compares request plus result policy.
- Persist client attachments as 90-second leases. Ensure accepts a clientId (generated when absent), returns lease metadata; attach by context ID, renew and release are owner-scoped endpoints. Renewal cannot revive expired tokens. Reattachment creates a fresh token. Job submission uses X-Linha-Client-Lease; existing idempotent jobs remain retrievable after retirement. Polling results never renews a backend.
- Serialize acquisition, submission and retirement through the context row. No live leases puts a version in DRAINING. Accepted queued, running, retrying and cancelling jobs keep capacity, including replacement after driver failure. Once all jobs are terminal, fence workers and retire all instances, ignoring minimum capacity, cooldown and idle timers. Reattachment reactivates the same version; already-draining instances are replaced. PostgreSQL clock and persisted leases survive HA server restarts.
- JVM client and context implement AutoCloseable. Handles in one client share a per-version attachment with reference counting; scheduled daemon heartbeats renew it. Closing the final handle releases it. Process death expires it. Renew failure is retried; expired attachments are reacquired by ID. SDK shutdown releases best effort; lease expiry remains authoritative.

## Risks / Trade-offs
Spark Operator becomes an external dependency. Worker images must retain Spark-compatible entrypoints and package the declared JAR; launch-script-only config must move into javaOptions, arguments or Pod templates. Resolving mutable tags adds registry latency to ensure and requires registry availability. Old clients do not heartbeat and must be upgraded. Mixed old/new server versions are unsupported across schema migration; deploy with migration coordination. Jobs that never terminate can hold a draining backend indefinitely; cancellation/deadlines remain explicit user controls.

## Migration Plan
Schema v5 backfills versions without changing context or job IDs and grants existing contexts a 90-second migration lease. Deploy upgraded server/chart and SDK clients with application settings. Old versions drain after lease expiry. Install Spark Operator v2.4.0 independently in the chosen namespace and grant Linha namespaced SparkApplication access. Validate on an isolated cluster before production rollout.
